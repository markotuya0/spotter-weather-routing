## 3. Assumption index

Full list in `01` §6 (A-01 … A-11). Added during the Phase 1 review: **A-12** (routes with unknown checkpoints rank below complete routes). Phase 1B re-scoped A-07 and A-12 from "extra ranking keys" to "separate eligibility policy" (D-21) — the assumption content is the same (blocked beats incomplete beats... no: eligible beats incomplete beats blocked), only *where* it's implemented changed. Provider-dependent assumptions that Gate 0 can confirm or change: truck mode and alternatives (D-03, D-05), time-vs-distance data (D-06), `traffic=false` effect, tile service terms (D-09).

**A-13 (added M2 security closeout, W-2, UNVERIFIED):** Render's production deployment puts exactly one trusted reverse proxy (its own edge load balancer) in front of the Django app, and that proxy reliably appends/overwrites the real client IP as the last entry of `X-Forwarded-For` rather than relaying whatever the client sent verbatim. `config/settings.py` sets `NUM_PROXIES=1` on this basis so DRF's throttling can't be trivially bypassed by a client spoofing `X-Forwarded-For`. This has not been confirmed against an actual Render deployment — needs a live check (inspect the XFF the app actually receives from a real external request) before treating the mitigation as proven; if wrong, it is overridable via the `NUM_PROXIES` env var.

## 9. M2 security closeout (2026-10-22, fix-before-approval)

An adversarial review of the M2 implementation raised 2 CRITICAL and 3 WARNING findings (C-1, C-2, W-1, W-2, W-3). All five were fixed/mitigated in this pass; see `docs/worklog.md` for the matching test IDs. Status legend: **FIXED** = verified closed by a regression test that fails if the fix is reverted; **MITIGATED** = risk reduced with a documented residual assumption that still needs live-environment confirmation.

- **C-1 (FIXED) — Retry-After robustness.** `backend/providers/http.py`: `_parse_retry_after` now accepts RFC 7231 delta-seconds or HTTP-date, rejects/clamps malformed, negative, NaN, Infinite, and excessively large values to `[0, MAX_RETRY_AFTER_S]` (20 s); a per-call `total_waited_s` budget (`MAX_TOTAL_WAIT_BUDGET_S`, 20 s) is enforced across every retry path (timeout, connection error, 429, 5xx) — once sleeping further would exceed it, the function raises a controlled `ProviderError` (carrying `retry_after_seconds` for 429) instead of blocking. 16 new tests in `tests/providers/test_http.py`.
- **C-2 (FIXED, with a documented residual risk) — credential security and deployment defaults.** `redact_url()` is now applied to every provider exception message before it reaches a `ProviderError`, and the original `requests`/`urllib3` exception is never chained (`raise ... from None`) so it can't surface via Django's own exception reporter even with `DEBUG=True` (`explicit_or_implicit_cause` in `django/views/debug.py` honours `__suppress_context__`). `config/settings.py`: `DEBUG` now defaults to `False` and `ALLOWED_HOSTS` to `localhost,127.0.0.1` (never `*`) — production (Render) must set `ALLOWED_HOSTS` explicitly, documented in `.env.example`. **Residual risk (undetermined, not fixed):** the original exception object still lives as a local variable (`last_exc`) in `request_with_retry`'s stack frame for the life of the call; if an APM/crash-reporting tool with local-variable capture (e.g. Sentry's `with_locals`) is ever added, it could surface the unredacted secret via that channel independently of the exception chain. No such tool is wired up today — flagging for whoever adds one later.
- **W-1 (FIXED) — single source of truth for risk.** `domain/models.CheckpointRisk` now carries the full breakdown (`raw_value`, `by_condition`, `load_rule_applied/name/from/to`) alongside `level`/`drivers`, all populated by the one classification pass in `domain/risk.checkpoint_risk()`. `trips/service._checkpoint_risk_detail` was rewritten to only read fields off that single result — it no longer calls `classify_wind/rain/snow` or `apply_load_rules` itself. Regression test `test_analyze_displayed_risk_consistent_with_ranking_risk` (`tests/trips/test_analyze.py`) forces `risk.checkpoint_risk` to a known value and asserts both the per-checkpoint API display and the route's aggregated `ranking_keys`/`summary.max_level` agree with it.
- **W-2 (MITIGATED, not fully verified) — rate-limit identity.** `NUM_PROXIES=1` is now set in `REST_FRAMEWORK` (overridable via env), making DRF's `AnonRateThrottle.get_ident()` key off the last `X-Forwarded-For` entry rather than trusting the whole client-supplied header. **This is an ASSUMPTION about Render's topology** (one edge proxy that reliably appends/overwrites the real client IP as the last XFF entry), not a confirmed fact — recorded in the assumption index. If Render's edge relays XFF verbatim instead of appending to it, or if the app is ever reachable without going through that edge, `NUM_PROXIES=1` reproduces the original spoofing vulnerability rather than fixing it. **Needs a live-deployment check** (inspect the actual `X-Forwarded-For` the app receives from a real client request on Render) before this can be upgraded to FIXED. Also noted: a client sending an empty `X-Forwarded-For` header collapses into a shared `''` throttle identity with every other client doing the same — low-likelihood edge case, not separately mitigated.
- **W-3 (FIXED) — error contract.** `trips/errors.py` now sanitizes `retry_after_seconds` (finite, non-negative, or `None`) through `_sanitize_retry_after()` on every path that can produce it: `DomainApiError`, upstream `ProviderError` (including `RATE_LIMITED`), and DRF's own `Throttled` exception (previously fell through to a generic `VALIDATION_ERROR` 400 instead of a `RATE_LIMITED` 429). Tests: `test_analyze_rate_limited_provider_error_returns_retry_after_seconds`, `test_analyze_application_throttling_returns_retry_after_seconds`, `tests/trips/test_errors.py`.
